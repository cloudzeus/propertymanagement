# PWA Φάση 2 — Web Push — Implementation Plan

> Executed inline (superpowers:executing-plans), TDD per task. Spec: `docs/superpowers/specs/2026-10-21-pwa-push-design.md`.

**Goal:** A user who turned on «Ειδοποιήσεις στο κινητό» in the bell receives a Web Push on their device whenever a `Notification` row is created for them.

**Architecture:** one `createNotifications()` helper (DB write + fire-and-forget `sendPushToUsers()`), `PushSubscription` Prisma model, `web-push` with VAPID from env, `push`/`notificationclick` handlers in `public/sw.js` (v2), a `PushToggle` client component in the bell footer driven by the pure `decidePushState()`.

## Global constraints
- Local `.env` DATABASE_URL = PRODUCTION. No test rows. Migration via `migrate diff` only; `migrate deploy` only after the user's explicit approval.
- Greek copy, `react-icons/ri` *Line only, `var(--fs-*)` sizes, no setState synchronously inside effects.
- Shared checkout: edit only the hunks this plan names in `lib/maintenance-requests.ts` (another session has uncommitted changes there); commit only this plan's files; never push/stash/reset.
- Known pre-existing failures: 9 tsc errors, ~339 eslint errors repo-wide, 2 failing vitest files (building-caps, ai assistant actions).
